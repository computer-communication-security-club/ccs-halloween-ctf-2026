## Architecture

The service runs a custom 16-bit VM (eight 16-bit registers, 64 KiB
little-endian memory, Z/C flags, 33 opcodes) over an encrypted firmware
image.

```text
nonce N (16 bytes) ──► encrypted firmware in HYDRA VM
candidate P (16 bytes) ──► verifier ──► accept/reject byte
                                         │
                                         └─ AUTH-OK + flag only if accepted
```

The firmware computes a target `H(N)` with a four-round 32-bit ARX routine and
applies a 16-step, nonce-dependent reversible permutation `G_N` to the
candidate proof. It accepts iff `G_N(P) == H(N)`. The unique valid proof is
`P = G_N^-1(H(N))`.

The downloadable binary **does not contain the inverse**. This is the key
design change from the earlier HYDRA prototype: the old binary exposed a
native nonce-to-tag routine that could be called from GDB. The current binary
contains only `verify_proof(nonce, candidate)`, which returns a boolean. GDB
can test candidates, but it cannot generate a valid proof. The firmware is a
real verifier, not decorative native logic: a successful authentication
executes 2,042 VM steps.

## Docker

One service, built from this directory. The builder and runtime use the
reviewed Debian bookworm-slim digest. The private runtime image copies
`flag.txt` to `/flag.txt` and runs as uid 10001 with a read-only filesystem,
`cap_drop: ALL`, `no-new-privileges`, 1 CPU, 256 MiB, and 128 PIDs.

```sh
docker compose up -d --build
uv run solve/solve.py 127.0.0.1 34001
docker compose down --volumes --remove-orphans
```

Readiness: the published TCP port returns `HYDRA-SVC/1.0 AUTH-REQUIRED` and a
32-hex `NONCE` line. The Docker healthcheck opens a connection without sending
a line, so it does not count as player activity.

### Repository integration check (2026-10-29)

`uv run tools/ctf.py dist challenges/rev/hydra-vm`, `check`, `dist --verify`,
and the 38-test organizer suite all passed from the repository checkout. The
committed `dist/` is byte-identical to a fresh Docker `dist`-stage build.

The local Docker engine on the authoring host is 29.8.0, which rejects every
container `exec` when `no-new-privileges:true` is set (including
`debian:bookworm-slim /bin/true`). That is an engine regression, not a
challenge failure. The committed Compose file retains the required
`no-new-privileges` setting. For a local functional check only, a temporary
Compose override with `no-new-privileges:false` was used; with it,
`uv run tools/ctf.py test challenges/rev/hydra-vm` built the image, became
healthy, and the solver recovered the flag. CI must confirm the same test on
its Docker version before merge.

## Security notes

- Flag is copied only into the private runtime image; `dist/` is scanned for
  plaintext flag bytes by `tools/ctf.py check`.
- Fresh nonce per connection; one AUTH attempt per connection; no replay.
- The verifier output is one byte. There is no tag, prefix, or intermediate
  result on the wire.
- `parse_hex16` checks exact length before indexing, fixing the earlier
  uninitialized stack read.
- VM memory is addressed with 16-bit indices, so guest accesses cannot escape
  the 64 KiB array. Invalid opcodes and step-limit exhaustion fail closed.
- No shell, file-path input, or network egress from the service.

Residual limitations: a local verifier remains a candidate-testing oracle
(players can check guesses), the 128-connection cap allows a bounded
slow-client denial of service, and a real independent test-solve by someone
other than the author is still required before freeze per `CONTRIBUTING.md`.
